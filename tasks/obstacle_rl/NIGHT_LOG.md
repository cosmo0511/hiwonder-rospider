### 01:20 검토 AI 1차 검수 (2-b 원인 분석) → 2-d, 2-e 준비
검토 AI 가 코드와 로그를 읽고 찾은 것 (코드에서 확인함):
1. **과속 원인**: "앞으로 나아가기"(가중치 5.0)는 느리면 감점, 빠르면 벌 없음. 블라인드 정책은 자기 속도를 몰라서 "일단 빠르게"가 최선. 속도 맞추기(허용 0.05)는 오차가 조금만 커도 점수 0 이라 신호가 없었음
2. **옆으로 새는 원인**: 속도 맞추기가 vx, vy 오차를 하나로 묶어서, vx 가 넘치면 vy 를 고칠 신호도 같이 사라짐. 기준 걸음의 RM 다리가 선 자세와 어긋나 한쪽으로 끄는 것도 의심
3. **톡톡 두 번 딛기 원인**: 미끄러짐 벌점이 닿은 발만 세서, 발을 띄우면 벌점이 줄어듦. 박자 접촉 점수도 "디딜 차례에 뜬 발"을 거의 안 벌함
4. 평가 도구: 옆 이탈 / 방향을 절댓값만 봐서 한쪽 쏠림을 못 봄, 중간 리셋 env 가 섞일 수 있음 → **고침** (부호 포함 값, 몸 기준 옆 속도, 리셋 env 제외 추가)

준비한 다음 실험:
- **2-d** = 2c_mass + (a) 앞으로 나아가기 끔, vx / vy 추종 분리 (b) 미끄러짐 벌점은 디딜 차례 발만 + 디딜 차례에 뜬 발 벌점 (c) 따라 하기 기준 = 선 자세 + wasd 움직임 (d) 위아래 출렁임 벌점 -0.5 → -2.0
- **2-e** = 2-d + 정책이 최근 4 스텝 관측을 같이 봄 (블라인드 속도 짐작)
- 2-c 결과를 보고 2-d 로 갈지 정한다

### 01:30 다국어 검색 (영어 / 중국어 / 한국어) → 중요한 참고 논문 발견
- 검색어 예: "六足机器人 强化学习 步态 Isaac Gym 奖励函数 三角步态", "hexapod RL stairs blind proprioception Isaac Lab", "6족 로봇 강화학습 보행 Isaac Lab 보상 설계", "blind policy observation history length"
- **가장 중요: Hiwonder JetHexa (RoSpider 와 같은 회사, 다리 구조 같음) 를 몸 감각만으로 학습해 계단 · 험지 통과** (Biomimetics 2026, https://pmc.ncbi.nlm.nih.gov/articles/PMC13509619/)
  - 방법: 다리마다 진동 신호기(Hopf CPG) 가 tripod 걸음을 만들고, **RL 은 3 개 값(걸음 크기, 걸음 빠르기, 좌우 회전)만 조절**
  - 결과 (4.7 m 코스 완주율): **CPG + RL 88 %** vs 고정 CPG 9 % vs **관절 18 개를 RL 이 직접 조종 20 %** ← 우리가 지금 하는 방식이 마지막 것
  - 관측에 **IMU 로 적분한 방향(yaw)** 을 넣고, 옆 이탈 / 방향 벌점을 크게 줌 (옆 이탈 제곱 -1.2, 방향 오차 제곱 -2.0, 레인 이탈 -2.5, 완주 보너스 150)
  - 회전 조절을 빼면 완주율 88 % → 13 % (옆으로 새서 실패) → 방향 보정이 핵심
- 기타: 블라인드 보행은 관측 히스토리 4 ~ 12 스텝을 많이 씀. 6족 계단 논문(Qu et al.)은 계단 높이 4.5 → 18 cm 커리큘럼 + 카메라 student
- **반영 계획**: 2-c 결과를 보고
  1. 우리 방식(관절 18 개 직접)을 2-d / 2-e 로 계속 고쳐 볼지,
  2. JetHexa 처럼 **CPG(우리 박자 + wasd 걸음) 위에서 RL 이 걸음 크기 · 빠르기 · 회전 + 작은 관절 보정**을 하는 혼합 방식(2-f)으로 갈지
  검토 AI 와 같이 정한다. 혼합 방식은 "걸음 모양은 확실히 + 장애물 앞에서 관절 보정으로 바꿀 여지"를 둘 다 가진다
- 공통으로 넣을 것: 관측에 **방향 오차(IMU yaw - 목표 방향)** 추가 (실물 IMU 로 얻을 수 있는 값)

### 01:45 혼합 방식(2-f) 코드 작성 + 검토 AI 2차 검수
- 새 코드: `cpg_action.py` (CPG 가 tripod 걸음, 정책은 걸음 크기 · 빠르기 · 회전 + 관절 보정 0.2 rad), 관측에 방향 오차 추가, `obstacle_eval.py` (obstacle_sweep 과 같은 방지턱 / 구덩이 통과율 평가)
- 검토 AI 2차 지적과 조치:
  1. **CPG 에 행동 0 을 줘도 검증된 wasd 걸음과 다름** (선 자세 오프셋이 더해지고, wasd 의 부드럽게 따라가는 필터가 빠짐) → **고침**: 0 중심 절대각 + wasd 와 같은 필터. 학습 전에 행동 0 으로 걸려서 베이스라인과 같은지 먼저 확인하기로 함 (`gait_eval.py --controller zero --exp 2f`)

  3. 2-d 의 "선 자세 + wasd" 기준도 검증된 걸음이 아니게 됨 → **취소**, 원래 기준 유지
  4. 박자 접촉 점수와 "디딜 차례에 뜬 발" 벌점이 겹침 → 박자 접촉 1.0 → 0.5

  - 정책이 최근 4 스텝을 기억 (블라인드가 발 걸림 / 단차를 알아챌 단서)
  - 관절 보정(0.2 rad)과 걸음 크기 범위는 그대로 (키우면 2-c 처럼 걸음이 무너질 위험)
- 2단계(3-a) 수정: 위아래 출렁임 벌점 -2.0 → -0.5 (방지턱 오르내림은 필요), 기울기 벌점 -0.2 → -0.1, 파이프를 로봇 뒤에 치우는 리셋 추가 (안 하면 파이프가 지형에 박힘), 마찰 0.4 ~ 1.0 (베이스라인이 마찰 0.5 에서 약함), 명령 하한 0.12 → 0.14 (커리큘럼 승급 여유), 지형 무작위 폭을 시드 따르게
- 평가 수정: 걸음새 평가는 항상 평지에서, 장애물 평가는 obstacle_sweep 과 판정을 맞춤 (몸통 닿아도 통과로 세고 따로 표시, 베이스라인 시작 박자 무작위 + 출발 전 1.5 s 서 있기), 베이스라인을 CPG 실험에 잘못 쓰면 바로 알려주는 에러
- 3단계 전략 (검토 AI 의견): 굴러가는 파이프 + 그레이팅 계단은 블라인드 단독으로 위험. **지형을 보는 teacher (높이 스캔 + 파이프 위치) 를 먼저 학습 → 몸 감각 + 기억만 쓰는 student 로 옮기기**. 실물에서는 손목 뎁스 카메라로 높이 지도를 만들어 같은 입력을 채울 수 있음. 2단계 결과를 보고 정함
- 순서: 2-f 끝(03:10쯤) → 2-f 평가 → **2-g 평지 학습** → 3-a (2-g 이어서, 방지턱 / 구덩이) → 장애물 평가 vs 베이스라인
