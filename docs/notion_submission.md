## 2. 과제 목표

### 해결하려는 상황

사용자가 RosPider 를 **WASD 로 원격 조종**하여 실내를 보행시킵니다. 조종자는 로봇의
카메라 영상만 볼 수 있고 발밑은 보지 못합니다. 이때 로봇은 전진 명령을 받더라도
**충돌할 물체 앞에서는 스스로 정지**해야 하고, **넘어갈 수 있는 2 cm 턱 앞에서는
정지하면 안 됩니다.** 그런 지형마다 멈추면 조종이 불가능해지기 때문입니다.

> 로봇이 매 순간 판단해야 하는 질문: **지금 전진해도 되는가?**

정지하지 못하면 충돌하고, 불필요하게 정지하면 조종할 수 없습니다. 따라서 본 과제는
"장애물의 유무"가 아니라 **"넘어갈 수 있는 지형과 충돌 대상의 구분"** 문제입니다.

### 센서 융합이 필요한 이유

RosPider 의 뎁스 카메라는 몸통이 아니라 **팔 끝에 장착**되어 전방을 **24.2도 아래로**
향합니다. 따라서 화면 아래쪽은 항상 바닥이고, "가장 가까운 뎁스"로 장애물을 찾으면
**바닥이 먼저 검출됩니다.**

흔한 대응은 화면 위쪽만 사용하는 방식(고정 ROI)입니다. 정지 상태에서는 잘 동작하지만
**보행을 시작하면 성립하지 않습니다.** 6족 보행은 세 다리씩 교대로 딛으므로 몸통이
계속 기울어지고, **화면의 어느 영역이 바닥인지가 매 프레임 달라지기** 때문입니다.

**IMU 는 거리를 재지 못하지만 중력 방향을 제공합니다.** 중력을 알면 뎁스 점마다
바닥으로부터의 높이를 계산할 수 있고, 바닥을 화면 좌표가 아니라 **기하학적으로**
제거할 수 있습니다. 높이를 알면 **3 cm 이하는 통과 가능**으로 분류하여 위 요구사항이
바로 해결됩니다.

| 센서 | 역할 | 없으면 |
|---|---|---|
| Depth | 전방 물체까지의 **거리** | 근접 정도를 알 수 없습니다 |
| IMU `projected_gravity_b` | 몸체 **자세**(중력 방향) | 어느 점이 바닥인지 알 수 없습니다 |
| IMU `lin_acc_b` | **충격** | 이미 충돌했는지 알 수 없습니다 |

두 센서는 화면을 나란히 보여주는 데 그치지 않고 **하나의 판정 변수로 결합됩니다.**
IMU 가 뎁스 점군을 중력에 정렬시키고, **정렬된 좌표에서만 거리 판정이 수행됩니다.**

제한하였습니다.

### 장면

바닥 + 장애물(0.2 × 0.24 × 0.15 m) + 뒷벽으로 구성하였습니다. 장애물은
`kinematic_enabled=True` 로 설정하여 **실행 중 위치를 바꿀 수 있으므로**, 거리 조건을
변경할 때마다 시뮬레이터를 다시 기동할 필요가 없습니다. 계단(4단, 단 높이 5 cm) 및
2 cm 턱 장면도 함께 구성하였습니다.

![장면 전체 모습](outputs/sensor_fusion/walk_t02.0.png)

### 센서 위치·방향·설정

**장착 위치는 실기 URDF 에서 그대로 계산한 값이며 임의 추정치가 아닙니다**
(`urdf_fk.py` 가 URDF 체인을 전개).

| 항목 | 값 |
|---|---|
| 뎁스 카메라 부착 | `link4` (팔 끝), base_link 기준 (0.13125, 0.0013, 0.25086) m |
| 카메라 하향각 | **24.2도**, 바닥에서 높이 0.367 m |
| 뎁스 데이터 | `distance_to_image_plane`, 160×120, **수평 화각 63.0도** |
| IMU 부착 | `base_link`, 오프셋 (0.0048, 0.0112, −0.0057) m, **yaw −90도** |
| 갱신 주기 | 두 센서 모두 `update_period=0` → **같은 물리 스텝에서 읽어 시점 차이 0** |

- 카메라 내부행렬은 실기 캘리브레이션(`camera_info.yaml`)을 해상도에 맞게 비례
  축소하여 **화각을 실기와 동일하게** 유지하였습니다.
- IMU 의 `gravity_bias` 를 `(0,0,0)` 으로 두어 `lin_acc_b` 가 **순수 운동가속도**가
  되도록 하였습니다. 충격 임계값을 단순하게 적용하기 위함입니다.

### 보행

삼각보행(tripod)으로 구현하였습니다. A조(LF, RM, LR)와 B조(RF, LM, RR)가 0.5 위상차로
교대하며, 주기 1.2 s, 발 들림 0.035 m, 몸통 높이 0.12 m, 실험 명령은 전진 0.10 m/s
입니다. 다리 기구학 상수도 URDF 에서 산출하였고, URDF 체인과 대조한 검증 오차는
**0.21 mm** 입니다(`test_gait.py`).

## 4. 구현 방법

### 처리 순서

```
 ┌─ 뎁스 ──► 역투영 ──► 점 집합 p (카메라 프레임)
 │                            │
 │                            ▼
 │              h = p·up − 바닥면   ◄── up = −R_cam←imu · g_imu
 │              d = p·forward                ▲
 │                            │              │
 └─ IMU 중력 ─────────────────┴──────────────┘
                              │
   마스크: 0.03 < h < 0.40 (바닥·천장 제거), 경로 폭 0.15, 유효거리 0.12~2.0 m
                              │
   d_fused = min(d | 마스크)
                              ▼
   판정  기울기>25° → STOP_TILT │ 충격 초과 → STOP_IMPACT
         d_fused<0.30 → DANGER │ <0.60 → WARN │ 그 외 CLEAR
                              ▼
   행동  DANGER/STOP 이면 **전진 명령을 차단** (후진·회전은 유지)
```

### 핵심 코드

**(1) IMU 의 중력을 카메라 프레임으로 옮깁니다 — 두 센서가 결합되는 지점입니다**

```python
g_cam   = normalize(projected_gravity_b @ r_cam_imu.T)   # 카메라 프레임의 중력
up      = -g_cam
forward = normalize(ez - (ez·up) * up)                   # 시선축에서 상방 성분 제거
```

**(2) 중력 기준 높이로 바닥을 제거하고 거리를 구합니다**

```python
height = (points * up).sum(-1) - ground      # ground = 관측 점의 하위 5 백분위수
mask   = (height > 0.03) & (height < 0.40) & (|dist_lat| < 0.15) & finite
d_fused = dist_fwd[mask].min()
```

바닥면을 **상수가 아니라 추정값**으로 쓴 점이 핵심입니다. 몸체가 숙여지면 카메라
높이가 실제로 낮아지는데, 상수로 가정하면 모든 점의 높이가 편향됩니다(조건 4 참조).

**(3) 두 센서가 함께 최종 판정을 만듭니다**

```python
decision = where(d_fused < 0.60, WARN,   CLEAR)      # 뎁스 기여
decision = where(d_fused < 0.30, DANGER, decision)   # 뎁스 기여
decision = where(tilt_deg > 25.0, STOP_TILT, decision)   # IMU 기여 (상위 조건)
```

`d_fused` 자체가 이미 IMU 로 정렬된 좌표에서 나온 값이고, 그 위에 IMU 단독 조건이
덮어씁니다. **두 센서가 서로 다른 층위에서 같은 판정 변수에 기여합니다.**

> 카메라가 팔에 달려 있어 팔이 움직이면 `R_cam←imu` 가 변하므로 **매 스텝
> 재계산**합니다. 실기에서도 서보 엔코더와 URDF 로 동일하게 계산하며, 시뮬레이터의
> 정답 포즈를 쓰지 않았습니다.

## 6. 결과 분석

### 단일 센서와의 차이

| | 뎁스 단독 | 고정 ROI | **융합 (Depth + IMU)** |
|---|---|---|---|
| 수평에서 거리 추정 | 바닥 때문에 0.43 m 포화 | 정상 | 정상 (오차 수 mm) |
| 20도 숙였을 때 | DANGER 오경보 | 0.721 → 0.413 저하 | **유지** |
| 2 cm 턱 | WARN (정지) | CLEAR | **CLEAR (통과)** |
| 계단 | WARN | **미검출** | 0.718 m 로 검출 |

융합으로 얻는 것은 세 가지입니다.

1. **자세와 무관한 거리.** 바닥을 기하학적으로 제거하므로 카메라가 어디를 보든
   임계값을 다시 잡을 필요가 없습니다.
2. **물리적 의미를 갖는 임계값.** 사선 거리가 아니라 중력 정렬 수평거리이므로
   0.30 m 가 문자 그대로 "로봇 전방 30 cm"를 뜻합니다.
3. **높이 정보.** 정지 대상과 통과 대상을 구분할 수 있습니다. 거리만으로는
   불가능합니다.

### 발생한 오류와 해결 과정

**(1) 비교 기준선이 자체 그리퍼를 측정하던 문제**

초기 실행 로그에서 뎁스 단독 거리(`d_naive`)가 장애물 거리와 **무관하게 0.0642 m 로
고정**되어 항상 DANGER 였습니다. 카메라가 팔 끝에 있고 시선축 방향으로 **그리퍼가
뻗어 있어 화면 중앙 하단에 항상 찍히기** 때문이었습니다(URDF 상 전방 0.070 m).

이 상태에서는 "융합이 단일 센서보다 낫다"는 결론을 낼 수 없습니다. 비교 대상 자체가
정상 동작하지 않기 때문입니다. **자체 신체 제거를 비교 기준선에도 동일하게
적용**하여 해결하였습니다. 자체 신체 마스킹은 융합의 고유 기능이 아니라 이 로봇에서
뎁스를 쓰려면 필수인 **공통 전처리**이며, 실기 코드도 동일하게 처리합니다. 이후
세 방식의 차이가 **중력 정렬 하나로 좁혀져** 비교가 성립하게 되었습니다. 5절의 모든
수치는 이 수정 이후의 값입니다.

**(2) URDF 자체의 불일치 — RM 다리**

보행 기구학을 URDF 와 대조하는 테스트에서 RM 다리에서만 17 mm 오차가 발생하였습니다.
`end_RM_joint` 의 원점이 나머지 다섯 다리와 달라 발끝 횡 오프셋이 −17.4 mm(타 다리
±1.5~3 mm), 링크 길이도 0.1113 m(타 다리 0.1156 m)였습니다. 상수를 다리마다 개별
산출하도록 수정하여 오차를 0.21 mm 로 줄였습니다.

**(3) 보행 중 충격 판정이 계속 발생한 문제**

발이 지면에 닿을 때마다 가속도가 튀어, 정지 기준(6 m/s²)으로는 보행 내내
`STOP_IMPACT` 였습니다. 현재는 임계값을 25 m/s² 으로 올려 회피하였으나 **근본적인
해결은 아닙니다.**

### 한계

1. **사각지대.** 장착 구조상 카메라 전방 약 0.29 m 이내 바닥이 보이지 않아, 그보다
   가까운 낮은 장애물은 **원리적으로** 검출할 수 없습니다.
2. **바닥 추정은 바닥이 보여야 동작합니다.** 벽에 바짝 붙으면 하위 백분위수가 벽이
   되어 전체 높이가 편향됩니다. 계단·경사에서는 "바닥 한 평면" 가정도 깨집니다.
3. **IMU 가 이상적입니다.** 시뮬레이터의 IMU 는 바이어스와 노이즈가 없습니다. 실기
   `imu_calib.yaml` 에는 축별 바이어스와 최대 약 3도의 축 비정렬이 기록되어 있어,
   **시뮬 결과가 실기보다 좋게 나오는 가장 큰 원인**입니다.
4. **보행이 운동학 모드입니다.** 다리는 보행 궤적대로 움직이지만 몸통은 명령 속도를
   적분해 직접 이동시켰으므로 **접지 물리가 반영되지 않았고, 몸통 기울어짐(최대
   2.92도)도 합성 모델**입니다. 측정값이 아닙니다. 물리 접지 보행은 PD 게인이
   검증되지 않아 이번 제출에서는 실행하지 않았습니다.
5. **측정 시점을 0 으로 맞춘 것은 시뮬레이터이기에 가능합니다.** 실기는 IMU 수백 Hz,
   뎁스 30 Hz 라 빠르게 기울어질 때 롤링 왜곡이 생깁니다.

### 개선 방향

- **충격 판정에 보행 위상 게이팅 적용.** 보행 위상을 이미 알고 있으므로 착지
  구간에만 임계값을 올리면 됩니다. 위 오류 (3)에 대한 근본적인 해결책입니다.
- **IMU 에 실측 바이어스·축 비정렬을 주입하고 상보 필터 적용.** `imu_calib.yaml` 의
  값을 그대로 쓸 수 있습니다. 한계 3번의 해결책입니다.
- **바닥면을 백분위수 대신 RANSAC 평면 적합으로 추정.** 경사와 계단에 대응할 수
  있습니다. 한계 2번의 해결책입니다.
- **물리 접지 보행으로 재실험**하여 실제 기울어짐을 측정하고 합성 모델과 대조합니다.
  한계 4번의 해결책입니다.
- **LiDAR 를 추가한 3센서 구성.** RosPider 는 `lidar_link` 도 URDF 에 보유하고
  있습니다.
